# Попередня перевірка виписки з ЄДР

Тестове для mono. Вебдемо читає PDF виписки українського ТОВ, перевіряє зв’язок даних із доказами на сторінках і показує працівнику висновки та подальші дії. Перевірка в межах PDF допомагає підготувати кейс до верифікації за даними ЄДР. [Положення НБУ №65, додаток 2, п. 21](https://zakon.rada.gov.ua/laws/show/v0065500-20/ed20261010#Text)

## Запуск

Потрібен Python 3.9 або новіший. Перший запуск встановлює PyMuPDF.

```bash
sh demo.sh
```

[Переглянути запис демо](output/demo.mp4).

Відкрийте [вебдемо](http://127.0.0.1:8765). Порт можна змінити через `sh demo.sh --port 8871`.

1. Виберіть **Стандартна обробка**. Натисніть доказ біля ЄДРПОУ, щоб побачити фрагмент. Унизу звіту є відкриті перевірки й дія **Передати далі**.
2. Запустіть **Інша компанія в заявці**, щоб побачити обидва коди й ручний маршрут.
3. Запустіть **Два коди компанії**, щоб відкрити обидва докази ескалації. У «Інших тестових сценаріях» є скан, змішаний PDF і помилковий код засновника.

Приклади пов’язані з вигаданими PDF у [output/pdf](output/pdf). Дія працівника зберігається на час поточного перегляду.

## Режими запуску

- **Локальне читання (`local`)**. Працює з PDF із текстовим шаром без зовнішніх викликів. Для висновку зі сторінки-зображення потрібна ручна перевірка.
- **Відтворення (`replay`)**. Підготовлені структуровані дані завантажуються за хешем конкретного синтетичного PDF. Правила й перевірка доказів виконуються наживо. Цей режим демонструє також сценарії зі сканами.
- **Живий виклик (`live`)**. OpenAI Responses API отримує текст або зображення сторінок. Модель повертає структуровані поля, а для проблемних перевірок може додати пояснення. У разі збою пояснення доступна дія з правила. Для запуску передайте `OPENAI_API_KEY` у середовище процесу. `MONO_MODEL` задає доступну мультимодальну модель зі структурованими відповідями. Типово використовується `gpt-4.1-mini`. Для зовнішнього виклику в демо використовуйте синтетичні PDF.

## Перевірка якості

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m eval.run
```

На трьох оригіналах із текстовим шаром у локальному режимі збіглися **18 із 18 значень шести критичних полів**. Дата формування збіглася в єдиному зразку, де її можна було розмітити з текстового шару. Це мала вибірка для перевірки підтримуваного макета. У режимі відтворення пройшли **8 із 8 синтетичних сценаріїв**, із нулем хибних `PASS` у заданих негативних прикладах. Живий виклик покрито тестами з підставним провайдером. Окремий замір якості живої моделі потребує ключа API.

Для локальної оцінки власних документів передайте шлях до приватного JSON.

```bash
.venv/bin/python -m eval.run --manifest eval/private/manifest.json --mode local
```

Формат запису відповідає прикладу нижче. `pdf` задається відносно файла розмітки або абсолютним шляхом. Звіт записує лише агрегати. Папка `eval/private` ігнорується Git.

```json
[
  {
    "pdf": "зразок.pdf",
    "date": "2026-11-24",
    "fields": {"code": "00073142"},
    "states": {"ubo": "section_absent"},
    "forbidden_pass": []
  }
]
```
