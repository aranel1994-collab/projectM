# Попередня перевірка виписки з ЄДР

Тестове для mono. Вебдемо читає PDF виписки українського ТОВ, перевіряє зв’язок даних із доказами на сторінках і показує працівнику висновки та подальші дії. Перевірка в межах PDF допомагає підготувати кейс до верифікації за даними ЄДР. [Положення НБУ №65, додаток 2, п. 21](https://zakon.rada.gov.ua/laws/show/v0065500-20/ed20261010#Text)

## Запуск

Потрібен Python 3.9 або новіший. Перший запуск встановлює PyMuPDF.

```bash
sh demo.sh
```

[Переглянути запис двох живих прогонів](output/demo.mp4). У першому прогоні клік по рядку ЄДРПОУ в таблиці підсвічує фрагмент виписки жовтою рамкою. Далі йде попередній прогін синтетичного скану з доказами на обох сторінках. Очікування відповіді скорочено під час монтажу.

Відкрийте [вебдемо](http://127.0.0.1:8765). Порт можна змінити через `sh demo.sh --port 8871`.

### Живий показ

1. Запустіть сервер із `OPENAI_API_KEY` у середовищі. Завантажте [синтетичну текстову виписку](output/pdf/standard.pdf), виберіть **Живий виклик моделі** й натисніть **Перевірити PDF**. Для цього прикладу поле заявленого ЄДРПОУ можна лишити порожнім.
2. Покажіть назву моделі та маршрут **Стандартна обробка**. У таблиці **Дані з виписки** клікніть по рядку **Код ЄДРПОУ компанії**. Праворуч на першій сторінці жовта рамка підсвітить `00073142`. Клік по рядку **Дата формування виписки** відкриє другу сторінку.
3. За потреби запустіть у тому самому режимі [синтетичний скан](output/pdf/scan.pdf). На ньому видно зчитані поля, сторінки з доказами й причину ручної перевірки.

### Готові приклади

Кнопки готових прикладів запускають відтворення.

1. Виберіть **Стандартна обробка**. Клікніть по рядку ЄДРПОУ в таблиці, щоб побачити доказ. Унизу звіту є відкриті перевірки й дія **Передати далі**.
2. Запустіть **Інша компанія в заявці**, щоб побачити обидва коди й ручний маршрут.
3. Запустіть **Два коди компанії**, щоб відкрити обидва докази ескалації. В «Інших тестових сценаріях» є **Компанія припинена**, **У процесі припинення**, скан і змішаний PDF.
4. Щоб перевірити нову виписку з текстовим шаром, завантажте її в режимі **Локальне читання**. За наявності додайте ЄДРПОУ із заявки.
5. Відкрийте **Історію перевірок** і натисніть будь-де на рядку. У збереженому звіті відкрийте доказ і перегляньте записану дію, якщо її збережено.

Приклади пов’язані з вигаданими PDF у [output/pdf](output/pdf). Кожна завершена перевірка додає рядок у локальну SQLite-базу `private/history.sqlite3`. Вибір дії з коментарем оновлює відповідний запис.

База зберігає звіт, включно з фрагментами доказів та зображеннями сторінок, які можуть містити персональні дані. Оригінальний PDF залишається у своєму джерелі. Папку `private/` ігнорує Git. Для репетиції на синтетичних PDF запустіть демо з окремою базою командою `sh demo.sh --history-db private/rehearsal-v2.sqlite3 --port 8871`.

## Режими запуску

- **Локальне читання (`local`)**. Працює з PDF із текстовим шаром без зовнішніх викликів. Для висновку зі сторінки-зображення потрібна ручна перевірка.
- **Відтворення (`replay`)**. Підготовлені структуровані дані завантажуються за хешем конкретного синтетичного PDF. Правила й перевірка доказів виконуються наживо. Цей режим демонструє також сценарії зі сканами.
- **Живий виклик (`live`)**. OpenAI Responses API отримує текст або зображення сторінок. Модель повертає структуровані поля, а для проблемних перевірок може додати пояснення. У разі збою пояснення доступна дія з правила. Для запуску передайте `OPENAI_API_KEY` у середовище процесу. `MONO_MODEL` задає доступну мультимодальну модель зі структурованими відповідями. Типово використовується `gpt-6.2-sol`. Звіт фіксує модель із відповіді API. Для зовнішнього виклику в демо використовуйте синтетичні PDF.

## Перевірка якості

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m eval.run
```

На трьох оригіналах із текстовим шаром у локальному режимі збіглися **18 із 18 значень шести критичних полів**. Дата формування збіглася в єдиному зразку, де її можна було розмітити з текстового шару. Це мала вибірка для перевірки підтримуваного макета. У режимі відтворення пройшли **10 із 10 синтетичних сценаріїв**, із нулем хибних `PASS` у заданих негативних прикладах.

Під час незалежного рев’ю коміту `aff59a6` виконано **48 обробок синтетичних PDF** через реальний API, по два проходи восьми сценаріїв на кожній із трьох моделей. У кожному проході маршрути збіглися 8/8. GPT-6.2 Sol мала 79/80 правильних значень на тексті й 27/28 на сканах за два проходи, приблизно 13,5 с і $0,015 на документ за оцінкою рев’юера. Ці виміри передують виправленням.

**Живий прогін оновленої версії.** 25.11.2026 у коміті `aec014f` через OpenAI API обробили один [двосторінковий синтетичний скан](output/pdf/scan.pdf) моделлю `gpt-6.2-sol`. Збіглися **7 із 7 розмічених значень**. Від надсилання запиту до отримання звіту минуло **22,4 с**. Звіт збережено в локальній історії з маршрутом «Ручна перевірка» та причиною `SCAN_SOURCE`.

Для оцінки всього набору через API передайте `OPENAI_API_KEY` у середовище й запустіть команду нижче.

```bash
.venv/bin/python -m eval.run --mode live
```

Живий eval показує поля за джерелами, маршрути, середній час і токени успішних відповідей на витягання. Пояснення моделі в цьому вимірі вимкнені.

Для локальної оцінки власних документів передайте шлях до приватного JSON.

```bash
.venv/bin/python -m eval.run --manifest eval/private/manifest.json --mode local
```

Формат запису відповідає прикладу нижче. `pdf` задається відносно файла розмітки або абсолютним шляхом. Звіт записує лише агрегати. Папка `eval/private` ігнорується Git.

```json
[
  {
    "pdf": "зразок.pdf",
    "date": "2026-11-24",
    "fields": {"code": "00073142"},
    "states": {"ubo": "section_absent"},
    "forbidden_pass": []
  }
]
```
