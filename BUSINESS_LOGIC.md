# Бізнес-опис агента попередньої перевірки юрособи для mono

Версія 0.4 · Робочий обсяг демо після рев’ю

## Задача

Працівник завантажує PDF виписки з ЄДР. Агент витягує реквізити з доказами, запускає правила попередньої перевірки і показує, що підтверджує документ, де є суперечності та що треба зробити далі. Працівник обирає наступну дію.

Для верифікації ідентифікаційних даних про державну реєстрацію Положення №65 передбачає дані самого ЄДР. Тому в демо агент виконує перевірки за PDF, а звірка з ЄДР залишається відкритою дією. [Положення №65, додаток 2, п. 21](https://zakon.rada.gov.ua/laws/show/v0065500-20/ed20261010#Text)

## Вхід і межі демо

- Один PDF виписки українського ТОВ. Заявлений код ЄДРПОУ можна додати окремим полем. Без нього звіт показує, що належність PDF до заявки ще треба підтвердити.
- За робоче припущення беремо **виписку про реєстраційну дію**. Підтримуваний формат визначаємо за заголовком і полями справжніх зразків. Документ із заголовком «ВИТЯГ» має окремий тип і потребує окремої перевірки шаблону. [Виписка після реєстрації ТОВ](https://diia.gov.ua/services/reyestraciya-tov-na-pidstavi-modelnogo-statutu/) · [Послуга отримання витягу](https://diia.gov.ua/services/vityag-z-yedr/)
- Для простого ТОВ у підтримуваному шаблоні виконуємо весь набір перевірок PDF. Для невідомого шаблону, іншої форми юрособи або складної структури показуємо доступні дані та причину ручної перевірки.
- Орієнтир для першого тесту — **три справжні виписки**, бажано дві текстові з різними макетами та один скан або змішаний PDF. З них беремо структуру для демо-PDF із вигаданими даними. Справжні PDF, ручна розмітка, сторінки та записи відповідей моделі з них зберігаються поза публічним репозиторієм.
- Інтерфейс, звіт, пояснення, README, memo та сценарій демо — українською. Технічні коди мають зрозумілі українські підписи в інтерфейсі.

## Як працює агент

1. Код перевіряє файл і визначає джерело по сторінках. Помилка відкриття, захищений файл і збій моделі мають різні повідомлення та дії.
2. LLM витягує поля в задану схему. Для кожного значення повертає номер сторінки й фрагмент. Коди ЄДРПОУ та номери записів зберігаються як рядки.
3. Для тексту код перевіряє, що фрагмент є на вказаній сторінці та відповідає потрібному полю й особі. Код засновника в розділі про власників не підтверджує код самої компанії. Вміст PDF використовується тільки як дані.
4. Сторінки-зображення LLM читає зі скану. Поруч зі значенням показуємо зображення сторінки й походження доказу. Якщо висновок залежить від скану, мінімальний маршрут — ручна перевірка з `SCAN_SOURCE`. Для демо достатньо одного проходу.
5. Код підбирає придатну версію правил, визначає застосовність, обчислює статуси й маршрут. Звіти відтворюються на тих самих підтверджених вхідних даних і версії правил. Повторне живе витягання може змінити вхід правил.
6. Звіт показує висновки та документ поруч. Клік по доказу відкриває сторінку й підсвічує фрагмент за однозначного збігу. Працівник обирає «Передати далі», «Запросити документ» або «Ескалація» і може додати коментар.
7. Для `REVIEW` і `FAIL` LLM пояснює вже обчислений результат на основі доказу, підстави та дозволеної дії. У разі збою звіт показує опис і дію з правила. Код визначає маршрут незалежно від пояснення.

## Стани, маршрути і звіт

Запис поля розрізняє знайдене значення, явну відмітку про відсутність відомостей, порожнє поле, відсутній розділ, нечитабельність, непідтверджене та суперечливе значення. Результат правила — `PASS`, `REVIEW`, `FAIL`, `NOT_APPLICABLE` або `NOT_CHECKED`. Відсутній розділ сам по собі не визначає застосовність правила.

- **`ESCALATE`** — є достатній доказ, а правило передбачає ескалацію. Демо-приклад — два коди, кожен явно наведений як код тієї самої компанії.
- **`MANUAL_REVIEW`** — потрібна дія на етапі PDF. Причини включають суперечність із заявленим кодом, непідтверджене критичне поле, скан як джерело висновку, непідтримуваний формат, складну структуру або відсутність застосовної версії правил.
- **`STANDARD`** — застосовні критичні перевірки підтримуваного PDF пройдено. У звіті залишаються відкриті зовнішні дії. Критичні поля етапу PDF задаємо за підтвердженим шаблоном. Для базового ТОВ це назва, місцезнаходження, власний код, дата й номер реєстраційного запису та відомості про виконавчий орган. Якщо очікуваний розділ власників або КБВ відсутній, це окрема причина для уточнення. Для шаблону, який за своєю структурою не містить розділу КБВ, встановлення КБВ залишається відкритою дією.

У звіті видно причини, докази, статуси та відкриті дії, редакцію джерела, дату перевірки, версії правил і моделі, версії промпту та схеми і режим запуску. У `live` модель викликається, у `replay` використовується збережена відповідь для конкретного PDF.

## Початкова оцінка і здача

Розмічаємо три справжні PDF вручну. Для кожного критичного поля записуємо очікуване значення або стан і сторінку. Показуємо результати як кількість правильних із застосовних прикладів, окремо для тексту і сканів, та рахуємо хибні `PASS`. Вказуємо, які зразки використали для налаштування, а які для контрольного прогону. Для зовнішньої моделі використовуємо синтетичні або знеособлені дані, якщо обробку оригіналів не погоджено. У підсумку фіксуємо, які файли й режими реально використали.

- **Демо** на вигаданих даних показує стандарт, ручну перевірку та ескалацію, докази з PDF і одну дію працівника.
- **GitHub** містить код, відтворюваний запуск, синтетичні PDF, розмітку до них та автоматичну оцінку.
- **Memo** до двох сторінок пояснює межу за додатком 2, п. 21, дизайн керованого пайплайна, роль LLM, результати оцінки і зміни для продакшну.

У memo описуємо звірку з ЄДР, установчі документи за кодом доступу, СЕІ за наявності договору, санкції й PEP, захист даних і розміщення моделі. Кейс-менеджмент охоплює отримання додаткового PDF у тому самому кейсі з новим запуском, історією та аудитом. Для змін правил передбачаємо моніторинг, регресію, погодження і ручний маршрут для зачеплених кейсів, якщо вимога вже застосовується й правило очікує публікації. [Положення №65, додаток 2, пп. 21–23](https://zakon.rada.gov.ua/laws/show/v0065500-20/ed20261010#Text)
